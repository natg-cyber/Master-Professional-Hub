# Complete workflow

## Entry: user profile, then route selection

At first use, ask the user to introduce their professional focus: sector or area, target roles/application types, and optional geography or coaching goal. Example: **urban planning / urban development; project coordination, development approvals, permitting, or construction administration**.

Use the coaching practice described in [methodologies](methodologies.md): clarify and reflect the user's goal, then support their choice without taking over. Use START when preparing behavioral interview examples; do not invent missing details.

Save the answer as a reusable professional profile. Reuse it while current; do not ask again unnecessarily. Then show the route selector:

1. **A job opportunity or application**
2. **Networking**
3. **Connect networking with an existing opportunity**

If the user states both the profile and route in one message, accept both. If the route is unclear, ask before beginning branch-specific intake.

## Route A — Job opportunity/application

```text
Select or add opportunity
  → One-time application intake (company, role, JD, resume, source)
  → Match assessment and senior recruiter first-pass/red-flag review (RF1...RF3)
  → Tailored resume draft using Google XYZ when evidence supports it
  → Senior recruiter first-pass review and comparable re-score
  → Explicit resume approval gate
  → Cover letter draft
  → User confirms application was submitted
  → If interview confirmed: employer research + technical questions + START practice
  → Review new evidence against open red flags
```

Ask only for missing fields required by the current phase. If the job page cannot be accessed, request the job description. The match score is an estimate, not a hiring probability. A cover letter cannot proceed as final until the applicable resume version is explicitly approved. Interview stories must use the user's real evidence.

## Route B — Networking

Choose one activity:

- **Explore a sector, role, or community:** define what the user wants to learn and a practical connection plan. Do not presume job seeking.
- **Prepare a conversation/contact:** distinguish verified facts, possible connections to confirm, and open questions; prepare an objective, opening, three questions, flexible structure, close, and optional message draft.
- **Record a conversation:** summarize only what the user reports; capture learnings, commitments, next step, and optional follow-up date.

Offer follow-up text as a draft. Do not send it. Show any proposed tracker row and wait for approval before writing.

For interview preparation, structure behavioral examples with START. For other networking next steps, agree on the action and timing conversationally with the user; do not apply an unrelated framework.

## Route C — Connect networking with an opportunity

1. Select an existing opportunity.
2. Select an existing contact/conversation or create one.
3. Preview the relationship and ask the user to confirm.

If no opportunity exists, offer to create/select one or return to the route selector. Linking records does not submit an application, send a message, or imply a commitment. Store IDs/relationships so the opportunity and networking records are not duplicated.

## Shared state and approval rules

- Keep one opportunity record per position and stable red-flag IDs within that opportunity.
- Track drafts and approvals by version. A new resume edit returns that version to `Proposed`.
- Before changing a workbook, show the exact change and wait for explicit approval.
- If a capability or source is unavailable, say so and offer a practical next step; do not simulate an action.
- An in-progress draft should survive changing workflow routes when persistence is available.
